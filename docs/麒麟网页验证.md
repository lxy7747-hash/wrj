# 麒麟 x86_64：先验证网页，再接入仿真引擎

本页记录在麒麟 Linux Advanced Server V10 x86_64 虚拟机上完成的网页侧验证。`WRJ_WEB_ONLY=1` 允许尚无 Linux `mission` 可执行文件时启动网页、API、WebSocket 和地图；此模式下发起仿真会明确报错。它不代表仿真引擎已通过验证。

## 发布内容

在开发机的 `frontend` 目录执行 `npm ci`、`npm run typecheck`、`npm run build:lan`。将 `dist/`、完整的 `server-dist/`、`scripts/`、`package.json`、`package-lock.json` 复制到服务器 `/opt/wrj/app/`。在服务器的 `/opt/wrj/app` 执行 `npm ci --omit=dev`。本次验证使用 Node.js 22.14.0（Linux x64）和 VersaTiles 4.6.0（Linux x86_64 musl）；地图文件、数据库及输入 CSV 另行复制，不能依赖 Git 发布包。

示例目录：

```text
/opt/wrj/app/{dist,server-dist,scripts,node_modules,.env.server}
/opt/wrj/runtime/bin/node
/opt/wrj/tools/versatiles
/opt/wrj/data/
/opt/wrj/input/{scenario_events.csv,position.csv}
/opt/wrj/runs/
/opt/wrj/maps/{china-taiwan-260823.pmtiles,taiwan-strait-satellite.pmtiles}
```

两份地图文件已从宿主机只读共享目录复制到虚拟机本地 `/opt/wrj/maps/`，复制后 SHA-256 与原文件一致。`/opt/wrj/app/.env.server` 的地图路径已切换到本地目录；运行中的 VersaTiles 不再依赖 `/mnt/hgfs/wrj_maps/`。宿主机共享目录中的原文件仍保留。

## 配置与运行

以下地址仅是本次 NAT 虚拟机的实例；服务器 IP 变化时，同步修改 `WRJ_PUBLIC_ORIGIN` 与需要绑定的 `WRJ_HOST`。`WRJ_PUBLIC_ORIGIN` 必须与浏览器实际访问的地址一致。

```dotenv
WRJ_DEPLOYMENT=lan
WRJ_WEB_ONLY=1
WRJ_PUBLIC_ORIGIN=http://192.168.40.128:8088
WRJ_HOST=192.168.40.128
WRJ_PORT=8088
WRJ_WEB_ROOT=/opt/wrj/app/dist
WRJ_OUTPUT_ROOT=/opt/wrj/runs
SCENARIO_DB_PATH=/opt/wrj/data/scenarios.db
WRJ_MAP_PORT=4175
WRJ_MAP_EXECUTABLE_PATH=/opt/wrj/tools/versatiles
WRJ_MAP_VECTOR_PATH=/opt/wrj/maps/china-taiwan-260823.pmtiles
WRJ_MAP_SATELLITE_PATH=/opt/wrj/maps/taiwan-strait-satellite.pmtiles
AFSIM_EVENT_LOG_PATH=/opt/wrj/input/scenario_events.csv
AFSIM_POSITION_LOG_PATH=/opt/wrj/input/position.csv
```

`MISSION_EXECUTABLE_PATH` 在仅网页模式中留空。复制已有 `runtime-config.db` 后，还需把库内保存的事件和位置文件路径改为 Linux 路径；只改 `.env.server` 不会覆盖库内配置。数据库和输出目录不能放在公开的 `dist/` 下。

在 `/opt/wrj/app` 执行：

```sh
/opt/wrj/runtime/bin/node --env-file=.env.server scripts/start-lan.mjs
```

当前虚拟机内网页和地图进程已启动，但没有配置开机自启；虚拟机重启后需重新运行。防火墙本次仅临时开放 8088/TCP，重启后若宿主机无法访问，需要按实际网络范围重新放行 Web 入口端口。地图服务只监听虚拟机本机，无需对客户端开放 4175/TCP。
