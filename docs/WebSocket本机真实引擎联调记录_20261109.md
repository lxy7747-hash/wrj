## 部署机验证步骤

1. 在可访问引擎服务的项目后端机器上，修改实际使用的 `.env.server`（发布包中为 `app/.env.server`）中的配置，然后重启项目后端。开发模式使用 `.env.local`；浏览器仍访问项目自己的页面和 `/ws/v1`，无需直接连接引擎地址。

   ```dotenv
   LINK_ENGINE_WS_URL=ws://192.168.1.48:8080/ws/v1
   ```

2. 确认远端服务控制的是本次测试任务，启动页面运行。当前实现是在本机 mission 启动成功后连接引擎 WebSocket；连接成功、运行有效后，暂停按钮才可用。
3. 点击暂停，核对后台实际收到两字段 `pause` 命令，并通过引擎状态或日志确认同一任务的仿真时钟暂停。页面应提示执行结果待确认，并允许手动恢复；仅有帧停止到达不足以判定暂停成功。
4. 点击恢复，核对后台收到 `resume`，同一任务继续推进，不新建运行。页面仍保留执行结果待确认提示。
5. 点击停止并完成二次确认，核对后台收到 `stop`，目标引擎实际结束。检查项目归档收尾、配置锁和按钮状态：仅远端引擎结束而项目启动的本机进程仍在运行时，当前实现不会凭发送成功自动解锁，须记录为状态对接问题。
6. 保存后台实际命令、引擎状态/日志、回执（如有）及页面截图。回执字段未确认前，继续区分“发送成功”和“执行成功”；出现失败或断线时不要自动重发控制命令。
