# 单次仿真结果、回放、报告和下载

适用于真实 mission 的本机及内网部署入口。

## 使用步骤

1. 在场景配置中点击“保存”，修正阻断错误后保存；Node.js 随后生成并写入 TXT。事件输出由 `src/config/app.config.ts` 的 `scenarioOutput` 统一开启，不再由用户在页面勾选。
2. 保存和 TXT 写入均成功后，页面自动选用刚保存的场景，核对版本并调用原有创建／启动接口；本地运行模式下由 Node.js 启动 mission。无需再确认“知道了”或点击“开始”。成功浮层显示 TXT 路径与启动结果，可前往态势主界面查看。执行仍在独立目录生成脚本和输出，不把保存的单个 TXT 当作完整运行包。
3. 引擎成功结束且结果解析通过后，“运行结果”自动选中本次执行。
4. 点击“查看回放”播放本次结果，或点击“查看报告／下载”进入对应报告。
5. 选择 HTML 或 CSV，点击“导出完整报告”。文件进入浏览器下载记录，可在另一台局域网电脑保存；不需要访问服务器磁盘路径。

报告和回放页面也可通过“运行结果”选择之前成功完成的执行。浏览器地址中的 `resultId` 固定来源，刷新、重新加载和导出均保持同一结果。没有选运行或归档时，仍可查看原来的配置文件数据，页面会明确标明来源。

若提示“场景配置已保存，但 TXT 写入未完成”，不会自动运行，应按定位错误处理生成问题。有运行／暂停任务、控制权限不足、版本变化或启动接口失败时，保留已保存配置和 TXT，明确提示未自动运行，不停止或恢复旧任务。离页、登出、重置或修改草稿会使在途保存流程失效，迟到结果不再触发后续启动请求；已经发出的启动请求不等于可撤销，运行状态以服务端为准。态势页原有“开始”入口保留。自动启动不等于引擎已成功完成；纯 Mock 模式仍仅改变投影，不调用真实进程。

独立脚本预览／预检入口已移除，保存流程内部仍使用相关生成与校验接口。评估报表保留 HTML/CSV 导出，不再提供“打印当前视图／另存 PDF”。

## 结果归属与保存

- 每次成功执行生成独立 `RESULT-…` 编号，记录场景编号、名称、修订、开始和完成时间。相同场景再次运行也不会覆盖旧结果。
- 在发布结果前，验证引擎退出码、控制台完成证据、事件完成记录，以及回放/报告的事件文件与位置文件 SHA-256 一致。
- 不补造阵营或链路质量测量。引擎 CSV 的空阵营保留为未提供；缺少的 SNR、BER 等指标仍显示暂无数据。
- 失败、停止、缺少事件文件或解析失败的任务不会发布成正常结果。结果损坏或编号不存在时明确报错，不回退到配置文件或其他运行。
- 在 `WRJ_OUTPUT_ROOT/results` 下原子保存带摘要校验的结果快照。服务重启后可重新读取已完成结果；原始脚本和 CSV 仍保留在 `WRJ_OUTPUT_ROOT/mission-runs`。
- HTML/CSV 报告包含结果编号、场景及修订、执行时间和来源文件摘要。HTML 作为附件下载，CSV 文本保留防公式注入处理。

结果列表为当前单实例共享目录，沿用业务查看和菜单访问权限；报告导出还要求普通报告导出权限。未实现按用户隔离的任务队列。

## 本地扩展 API

这些是实际文件运行入口的扩展，不改变原有确定性 Mock 契约。

| 请求 | 用途 |
|---|---|
| `GET /api/v1/mission-results` | 按完成时间倒序返回结果记录数组，使用现有成功信封 |
| `GET /api/v1/mission-results/:resultId` | 返回 `{ record, replay, report }` 快照，使用现有成功信封 |
| `POST /api/v1/reports/:reportId/export?resultId=RESULT-…&download=1` | 下载指定结果的 HTML/CSV 附件；请求正文为 `{ reportId, format }` |

记录字段：`resultId`、`scenarioId`、`scenarioName`、`revision`、`startedAt`、`completedAt`。不接受客户端磁盘路径。快照不存在返回 404，损坏/读取失败返回 503，报告和结果不匹配返回 409，非法来源参数返回 422。会话和权限失败分别为 401/403。

原有报告导出接口也支持 `download=1`，包括配置文件报告和 `archiveId` 指定的归档报告。`resultId` 与 `archiveId` 不可同时提供。省略 `download` 保持原来的 JSON 导出回执，兼容已有调用方。

## 更新与备份

运行 `npm run build:lan` 后更新部署中的 `app/dist` 和 `app/server-dist` 全部文件。没有新增 npm 依赖，不需要修改现有账号或业务数据库。

备份需包含 `data` 和 `runs`（自定义部署则为 `WRJ_OUTPUT_ROOT`）。原有数据库备份不包含输出目录中的结果快照。整目录压缩前先停服。

旧输出不会自动冒充新结果。本功能上线后完成的运行才自动登记；旧文件仍可通过原来的配置文件入口读取或归档。

此改造不包含运行中任务的断电恢复、真实引擎暂停/倍速、批量调度或新增链路质量测量。
