## 已接入

| 页面操作 | 实际上行报文 | 页面及后端行为 |
| --- | --- | --- |
| 播放 | 无上游启动报文 | 从已保存场景建立独立接收会话和模板映射，连接发送方，不启动本机 mission.exe |
| 暂停 | `{"msg_type":"sim_control","action":"pause"}` | 已绑定运行且连接正常时开放；发送后显示结果待确认，可再次点击播放恢复 |
| 暂停后点击播放 | `{"msg_type":"sim_control","action":"resume"}` | 沿用当前运行；不重新启动任务、不发送 START |
| 停止 | `{"msg_type":"sim_control","action":"stop"}` | 沿用权限检查和二次确认；可发送时发出 stop，随后停止本地接收并保存数据，归档成功后解锁；执行结果仍待确认 |
页面仅保留播放、暂停、停止，不增加其他结束按钮或内部 DISCONNECT 命令。

入口仍是页面 → 项目后端 REST → 引擎 WebSocket。请求不附带版本、请求编号、任务编号或运行编号，也不发送后台尚未确认的 GET_STATE。

配置沿用 `LINK_ENGINE_WS_URL`；设置后使用独立远端接收，页面点击“播放”建立连接，不要求本机 mission.exe 存在，也不启动本机进程。未配置时维持原本机开始/停止逻辑。一次只绑定一个接收会话；192.168.1.48 是数据发送方，部署方需确认命令在该连接上的实际作用对象。

用户已提供部署服务地址，WebSocket 配置为 `LINK_ENGINE_WS_URL=ws://192.168.1.48:8080/ws/v1`。按用户说明，当前联调环境无法访问该地址；需在可访问服务的部署机填写 `.env.server` 并重启项目后端。地址已知，网络可达性和真实执行结果尚未在本环境验证。

## 发送状态与真实运行状态

`SimulationRun.engineControl` 是新增的可选字段，仅包含 `connected`、`action`、`delivery`。它随 REST 运行列表/详情返回，运行状态通知触发页面重新读取；刷新页面后仍可恢复服务端记录的发送状态。

远端会话另有 `executionSource=REMOTE_WS`，`processId=null`。RUNNING / STOPPED 描述本地接收会话，不是远端仿真状态回执。时钟来自收到的规范帧；页面订阅不依赖本机位置或质量文件，场景节点使用配置位置。当前协议仅包含部分设备/探测位置，不提供完整动态节点位置流。

| delivery | 含义 | 后续操作 |
| --- | --- | --- |
| IDLE | 尚未发送控制命令 | 连接正常且运行活动时允许暂停、停止 |
| SENDING | 正在写入 WebSocket | 暂时禁止并发操作 |
| SENT | 写入连接完成，执行结果待确认 | 暂停后可手动恢复，恢复后可手动暂停；停止完成本地保存后重新开放播放 |
| UNKNOWN | 发送异常、超时，或发出控制后连接断开 | 不自动重发；需核实引擎，重连本身不消除不确定性 |

暂停/恢复的 HTTP 202 表示发送完成，响应仍为运行信封；不表示引擎已经执行。规范状态、仿真时钟及配置锁不会仅因 202 改变。发送等待上限为 3 秒，小于现有前端 HTTP 请求超时 5 秒；超时及迟到回调不冒充发送成功。

没有回执时，页面在“最后已知运行状态”之外持续展示待确认提示。不会用数据静默、连接关闭或自造回执推断已暂停/已停止。暂停后手动点击恢复是用户明确发起的后续操作，并不是自动重试或对真实暂停状态的确认。

停止按钮一并完成本地收尾：可发送时发送 stop，随后断开本地连接及重连计时器，等待 JSONL 和可生成的规范 CSV 收尾，再释放本地配置锁。归档失败保留错误与锁，再点停止可重试本地保存，不重复发送控制命令。断线或控制结果不确定时也能停止本地接收；停止后保留实际发送状态，不宣称发送方执行成功。该动作不确认发送方已停止。缺少规范 CSV 必需字段时写入缺测清单，原始含义不完整的数据仍按规范帧保存在 JSONL，不补造值。
