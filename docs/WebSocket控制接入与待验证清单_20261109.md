# WebSocket 暂停、恢复、停止接入与待验证清单

日期：2026-11-09。以后台确认的两字段请求为准；批量仿真不纳入。本清单区分代码发送能力与引擎执行确认，不以固定样例或发送成功替代真实执行证据。

## 已接入

| 页面操作 | 实际上行报文 | 页面及后端行为 |
| --- | --- | --- |
| 暂停 | `{"msg_type":"sim_control","action":"pause"}` | 已绑定运行且连接正常时开放；发送后显示结果待确认，可手动点击恢复 |
| 恢复 | `{"msg_type":"sim_control","action":"resume"}` | 沿用当前运行；不重新启动任务、不发送 START |
| 停止 | `{"msg_type":"sim_control","action":"stop"}` | 沿用权限检查和二次确认；发送后保持连接、归档及配置锁，不立即杀进程 |

入口仍是页面 → 项目后端 REST → 引擎 WebSocket。请求不附带版本、请求编号、任务编号或运行编号，也不发送后台尚未确认的 GET_STATE。

配置沿用 `LINK_ENGINE_WS_URL`；本机 mission 成功启动后建立连接。未配置时维持原本机开始/停止逻辑。当前仍是一个引擎连接绑定一个运行；部署方须保证上游服务控制的是本机所启动的同一场仿真。

## 发送状态与真实运行状态

`SimulationRun.engineControl` 是新增的可选字段，仅包含 `connected`、`action`、`delivery`。它随 REST 运行列表/详情返回，运行状态通知触发页面重新读取；刷新页面后仍可恢复服务端记录的发送状态。

| delivery | 含义 | 后续操作 |
| --- | --- | --- |
| IDLE | 尚未发送控制命令 | 连接正常且运行活动时允许暂停、停止 |
| SENDING | 正在写入 WebSocket | 暂时禁止并发操作 |
| SENT | 写入连接完成，执行结果待确认 | 暂停后可手动恢复，恢复后可手动暂停；停止发送后等待进程结束或后续真实确认能力 |
| UNKNOWN | 发送异常、超时，或发出控制后连接断开 | 不自动重发；需核实引擎，重连本身不消除不确定性 |

HTTP 202 表示发送完成，响应仍为运行信封；不表示引擎已经执行。规范状态、仿真时钟及配置锁不会仅因 202 改变。发送等待上限为 3 秒，小于现有前端 HTTP 请求超时 5 秒；超时及迟到回调不冒充发送成功。

没有回执时，页面在“最后已知运行状态”之外持续展示待确认提示。不会用数据静默、连接关闭或自造回执推断已暂停/已停止。暂停后手动点击恢复是用户明确发起的后续操作，并不是自动重试或对真实暂停状态的确认。

本机进程完成事件可以独立证明该本机进程已结束：正常结束且此前请求了停止时显示 STOPPED；异常退出显示 ERROR。仍需等待引擎帧归档收尾及现有进程安全检查后释放锁。若 WebSocket 控制的是另一个外部进程、而本机进程没有结束，本次实现不会凭发送成功解锁。
