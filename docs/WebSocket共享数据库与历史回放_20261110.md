# WebSocket 共享数据库与历史回放

## 数据归属和保存

- 所有场景、所有运行共用一个 `engine-history.db`，放在 `SCENARIO_DB_PATH` 所在目录。本机配置对应 `H:/Project/newWrj/data/engine-history.db`。此文件在新版后端首次启动时创建。
- `engine_runs` 固定保存运行 ID、场景 ID、任务、修订、开始时间和当次链路绑定；`engine_frames` 保存完整的标准化引擎帧；`engine_items` 保存用于按时间查询的事件、选路切换及告警。
- 每次播放创建独立运行；帧以运行 ID、引擎轮次、帧号唯一标识。同一场景的多次运行和不同场景互不混用。时钟重置后的引擎轮次也分别回放。
- 4173 接收、校验和适配上游报文后，逐帧写入原 JSONL 归档和共享数据库，继续生成 CSV。仍按已确认口径使用 `frame_id` 对应仿真秒数，不要求 `sim_time_s`，不修改实际帧里的数值口径。
- 完整标准化帧保留上游已适配的字段，并非逐字保存原始 WebSocket 文本。未确认的时延单位、总复合损耗口径继续按原值展示并标记。

## 保存失败与历史兼容

- 保留现有写盘背压和停止重试：文件或数据库失败，待写帧不移出队列，运行保持锁定；再次点击停止重试保存，不重复发送 stop。数据库按帧幂等写入，重试不重复留存。
- 停止必须完成文件、数据库及原有报表保存流程，成功后才解锁。此重试是当前后端进程内的恢复流程，不代表已实现异常断电后的自动续写；保存失败时应先处理磁盘问题并重试，避免强制退出。
- 不删除、不覆盖已有结果、JSONL 和 CSV。旧结果第一次打开历史回放时，校验原归档摘要和帧数后事务导入数据库；失败整体回滚，修复后可重试。没有引擎帧归档的旧结果仍使用原文件轨迹回放。
- 备份和迁移应同时保留原 `output/results`、`output/engine-frames` 和数据库。原系统备份的范围未扩展；完整旧归档仍可重建历史数据库。

## 页面和接口

1. 在“历史回放”的运行结果选择器中选中已完成的一次运行。
2. 原文件提供地图位置；新增“历史引擎数据”面板展示质量指标、选路与告警、事件。时间轴取文件与所选引擎轮次的较大时长。
3. 按游标读取不晚于该时刻的最近一帧；质量只显示该帧实际测量，事件、切换、告警显示该轮次游标之前的记录。暂停冻结，向后拖动清除未来记录，切换运行清空旧数据。
4. 帧间复用缓存，跨帧边界再读取历史接口。历史回放不发出播放、暂停或停止的引擎控制命令，也不启动上游接收。
5. 事件、切换、告警各显示最近 200 条，超出会提示；数据库和完整 JSONL 不因页面限额裁剪。

新增只读接口：`GET /api/v1/mission-results/:resultId/engine-replay?time=3775&epoch=0`。

- `time` 为非负仿真秒数；`epoch` 可省略，默认第一个已保存轮次。
- 继续要求登录和 `REPORT_RESULT_READ` 权限。由已保存结果推导场景及运行，拒绝额外传入 `runId`、`scenarioId` 替换归属。
- 使用原 `ok/data/meta` 响应封装；数据包括运行、场景、轮次目录、当前帧、下一帧时刻和历史事件集合。没有归档时 `data=null`，非法参数 400，结果不存在 404，归档或数据库异常 503。
- 共享前后端类型及校验位于 `src/features/replays/engine-replay.ts`；数据库实现位于 `server/local/engine-frame-sqlite.ts`。
