日期：2026-11-09。最新界面按用户要求恢复为“播放／暂停／停止”，暂停后再点播放恢复；停止合并本地保存和断开连接，不再提供单独结束按钮。最新验证见 `output/restart-ws-20261109/`。依据用户确认：192.168.1.48 是数据发送方；newWrj 接收、展示、留存并发送三类控制命令。兼容 V1.2 大纲、新模板及 websocketNew，批量仿真不纳入。

## 已完成的代码路径

最新三按钮版本验证：566 项相关回归通过、0 失败、0 跳过；类型检查、契约校验、前后端构建通过。真实浏览器验证播放→暂停→播放恢复→停止，测试发送方仅收到 pause/resume/stop，留存 79 帧，本机引擎启动 0 次。5173 前端和 4173 后端已重启并保持运行；实际 192.168.1.48 连接握手超时，点击停止仍完成本地收尾。最新结果：`output/restart-ws-20261109/play-validation-summary.json`，页面截图：`output/playwright/play-three-buttons-main.png`。

页面 → 项目后端 HTTP（连接及控制操作）→ 发送方 WebSocket；发送方帧 → 项目后端转换、归档 → 项目 `/ws/v1` → 页面。两段 WebSocket 分别负责上游数据和浏览器实时展示。

- 配置 `LINK_ENGINE_WS_URL` 后不创建本机执行器，不要求 mission.exe 路径；部署配置校验也不再检查该文件。未配置时保留原本机模式。
- 页面“播放”创建单个独立会话，以已保存场景生成与交付模板一致的实例名、端口映射。不执行脚本，不向发送方发送启动命令。
- `executionSource=REMOTE_WS`，进程号始终为空。内部 RUNNING / STOPPED 表示本地接收生命周期，不能作为发送方执行回执。
- 浏览器按接收会话建立实时订阅，普通状态更新不反复重连；远端模式不读取本机位置、进程日志或质量文件。链路、质量、事件等复用现有帧展示；节点位置使用场景配置，完整动态节点位置流待发送方提供。
- 暂停、恢复、停止原样发送 `{"msg_type":"sim_control","action":"pause|resume|stop"}`，其中 action 每次取一个实际值；不添加请求编号或运行编号。暂停后允许手动恢复，停止仍需二次确认。
- `SENT` 仅表示写入连接成功。无回执时持续显示待确认；控制发送失败或断线进入 UNKNOWN，不自动重发。
- “停止”经过权限检查和二次确认，可发送时发出 stop 后停止本地接收；连接不可用时仍可本地停止。待 JSONL 和可生成的规范 CSV 收尾成功后才释放本地配置锁。失败保留锁和错误，再点停止只重试本地保存，不重复发送控制命令。
- 接收帧按场景/修订/任务/运行留存，包含源帧号及重连轮次。规范 CSV 缺少必需字段时写入缺测说明，完整规范帧仍留存 JSONL，不用固定值补齐缺测。

单位沿用已确认口径：`sim_time_s` 按毫秒转内部秒；探测频率 GHz 转 Hz；帧号正常步长 5，对应 5 秒。模板文件和批量仿真均未扩展。

## 配置与使用

本机 `.env.local` 已设置以下值；部署包在实际使用的 `app/.env.server`（源码部署为 `.env.server`）配置同一项，重新构建部署并重启项目后端后生效：

```dotenv
LINK_ENGINE_WS_URL=ws://192.168.1.48:8080/ws/v1
```

1. 登录并选择与发送方数据相符的已保存场景，点击“播放”。
2. 确认帧号/时间推进，查看链路状态、质量及事件；配置与命令仍由项目后端校验。
3. 依次点击暂停、播放恢复、停止，后台检查实际收到的两字段报文。页面只提示发送结果，不虚构执行确认。
4. 点击停止即完成本地记录；完成后可再次点播放，并创建新的接收记录。

开发归档目录为 `frontend/output/engine-frames/<runId>/`；部署归档在 `WRJ_OUTPUT_ROOT/engine-frames/<runId>/`。持续接收期间使用待完成文件，结束后发布完整 JSONL、摘要及规范 CSV 的输出/缺测清单。这里不生成“本机 mission 正常完成”的报告记录。
