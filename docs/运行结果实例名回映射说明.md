# 运行结果实例名回映射

## 编号边界

- 对接 TXT 使用模板实例名；场景原编号及已保存配置不变。
- 新包 `mapping.json` 声明 `platformNaming: "TEMPLATE_INSTANCE"`；`platforms[].platformId/name` 是原编号与实例名的唯一对照。
- `devices`、`businesses`、`motion`、`jammers`、`sensors`、`linkCalc.hostPlatformId` 继续使用实例名；链路、设备和干扰机编号不改写。
- 读取端只对有上述标记的包转换一次，未知平台名原样保留，重复实例名或原编号拒绝读取。映射只作用于副本。
- 节点显示名称优先取对应场景平台的 `name`。源文件和来源 SHA-256 不变。
- 无标记的历史包保持原样，不猜测编号，也不自动迁移已有归档；曾生成实例名但未带标记的包需重新生成运行。

## 读取调用点核对

以下位置均按函数名定位，不包含 import 或类型引用。

| 调用位置 | 处理方式 |
| --- | --- |
| `server/local.ts` 配置位置路径 → `createPositionReader` | 不转换：外部配置文件没有权威运行包对照表。 |
| `server/local.ts` 配置事件/位置路径 → `readLocalReplay` | 不转换：同上，保留文件平台标识。 |
| `server/local.ts` 配置事件/位置路径 → `readLocalReport` | 不转换：同上。 |
| `server/local/mission-position-reader.ts` 本次运行 → `createPositionReader` | 读取后通过 `engineNameMap/toScenarioId` 转换，再按原平台编号筛选；不凭原编号优先匹配实例名。 |
| `server/local/mission-results.ts` capture → `readLocalReplay` | 传入本包映射及场景名称，位置在节点关联校验之前转换。 |
| `server/local/mission-results.ts` capture → `readLocalReport` | 传入同一映射，报告节点、连接、设备和侦测事件使用场景编号。 |
| `server/local/mission-results.ts` capture → `readAfsimLogFile` | 传入同一映射，转换后的事件用于筛选索引与规范事件 CSV。 |
| `server/local/afsim-log-reader.ts` loadInitialNodes → `readAfsimLogFile` | 透传可选映射；小文件与大文件流式汇总均转换。带映射的运行快照不复用外部文件的名称缓存。 |
| `server/local/report-file.ts` readLocalReport → `readAfsimLogFile` | 透传可选映射；配置文件路径不传，本次运行路径传入。 |
| `server/local/report-file.ts` readLocalReport → `readLocalReplay` | 透传同一映射与场景显示名，保持报告/回放身份一致。 |

补充：`readLocalReplay → readInitialNodes` 透传映射；`mission-runner → ContinuousTimeSeriesWriter` 读取本包标记并传入映射。连续事件归档及其筛选索引使用场景编号，避免大日志与内存快照口径不同。`resolveManifestConnections` 和 `publishReportFilterIndex` 使用转换后的设备端点副本，落盘的 mapping.json 不变。

## CSV 1.1 核对结论

`src/contracts/domain-models.ts` 的五份规范 CSV 表头声明平台端点列；`src/features/data-exchange/quality-records.ts` 明确以 `SourcePlatform/DestPlatform` 对照当前场景链路的 `sourcePlatformId/targetPlatformId`。因此规范 CSV 平台列使用场景原编号，不保留模板实例名。

事件的 `SourcePlatform/TargetPlatform` 及 Parameters 内明确的平台字段、质量/状态/损耗/切换文件的 `SourcePlatform/DestPlatform` 均在规范副本中转换。设备字段（包括原生事件中实际表示设备的 `system_platform`）、消息编号、链路编号、数值和诊断原文不替换。规范副本单独计算内容哈希，`sourceSha256` 仍对应未修改的引擎原文件。未修改 CSV 版本、表头或冻结合同。
