# 系统备份与恢复

系统备份保存场景、模板、账号、装备、角色权限、主数据、历史归档和白名单配置。审计及文件读取记录保留当前值，不随恢复回退；源 CSV、`output/results`、环境凭据和密钥不在备份范围内，恢复也不会删除历史结果文件。备份未加密，仅适用于非敏感开发数据。

恢复先在同一事务锁定时点保存当前原始快照，再严格校验来源并恢复。当前库的业务数据不合规时仍可保留原始预备份；该预备份标为 `INVALID`，只证明原始内容已保存，不能宣称可安全恢复。结构不完整、预备份写入失败或登记失败仍会阻止恢复。来源和恢复后数据须通过完整校验，写入失败整体回滚。

恢复会将账号及密码还原到备份时状态，之后新增的账号可能消失。执行前须确认掌握备份中的管理员凭据；管理员全部停用时不能保证通过在线鉴权进入恢复流程。

正式 `INVALID` 备份和旧主库备份不可在页面选择恢复。Mock 的 `INVALID_FIXTURE` 继续用于演示失败流程。直接请求无效来源仍返回原有含 `prebackupId` 的 `FAILURE` 结果，保留预备份；未改成提前拒绝，也未改变冻结响应合同。

备份文件写入后不再修改，列表校验结果不按时间到期。系统备份在 `catalog.db` 登记文件指纹（文件身份、大小、修改时间）、登记摘要对应的校验规则版本及结果；列表只读取文件元数据并与登记比对，一致时沿用结果，不重算 SHA-256。文件、登记摘要、表结构或校验规则版本变化时重新完整校验并回写；旧目录自动补列，已有备份首次列出时完整校验一次。校验遇到 SQLite 占锁（BUSY／LOCKED）、打开失败或临时 I/O 错误时，本次列表显示“校验失败”但不缓存、不登记，下次刷新重新校验；只有摘要不符、文件损坏、结构或业务内容不合规才登记为无效。旧主库备份仅在本进程内按同样指纹缓存。恢复不使用列表结果，仍读取来源、核对摘要并完整校验。

恢复前原始备份在写锁内只做写入后回读的一次结构校验，业务校验推迟到首次列出时完成；完成前不可选作恢复来源。当前数据合规时该预备份随后显示“校验通过”，可用于撤销本次恢复。

计划名称变更不移动下一次执行时间。新启用或改变执行间隔会从保存时刻重新计算；停用清空执行时间。停机错过的周期启动后仅补执行一次，最近 20 条执行记录用于展示，历史记录不自动清理。

## 长期计划启用前的待确认方案

容量保护建议使用三个可配置边界：备份完成后必须保留的磁盘剩余空间、单次备份大小上限、备份目录累计大小上限。具体数值须经确认后实施；本轮尚未增加容量拦截。

创建前估算本次备份和临时写入需要的空间，任一边界不满足就拒绝新建，明确提示剩余空间、所需空间、触发的限制和人工处置方式。计划执行记为失败；恢复前预备份无法完成时阻止恢复。写入中仍处理磁盘不足并补偿本次未登记文件，不自动删除旧备份或执行记录。

当前系统快照会在内存中物化并序列化全部表数据。启用长期计划前还须确认最大业务数据量、可接受的暂停时间及目录容量；本轮临时库回归不构成大数据规模验证。分块、流式备份、离机导出及外部导入均尚未纳入实现范围。
