# websocketNew 适配与待验证清单

依据：V1.2 评审修改版测试大纲、`场景配置参数对接/websocketNew` 的四份帧样例及用户确认的单位口径。兼顾现有 `comm_PerDefinition` 模板，本次不修改模板，不纳入批量仿真。

## 本次已实现

| 内容 | 接入规则与结果 |
| --- | --- |
| 帧号与时间 | `frame_id` 正常按 5→10→15 递增，每次仿真推进 5 秒；`sim_time_s` 实际为毫秒，接收入口除以 1000。页面、筛选、WS 转发与归档仍使用源时间换算后的秒值。正常帧号差 5 不提示异常或打断曲线；非正常间隔记录诊断并保留曲线断点，不补造中间帧。 |
| 探测与干扰频率 | 探测器 `jammer_sensor.events[].freq_band_hz` 按 GHz × 10⁹ 转 Hz；干扰机 `rf_jammer.active_params.freq_band_hz` 保持 Hz。按字段位置转换，不按数值大小猜单位。 |
| 链路频率 | 优先读取 `quality.input_trace.frequency_ghz`，兼容旧字段名 `frequency`。页面显示 GHz。 |
| 损耗 | 雨衰、云衰分别接收、展示和归档。总复合损耗保留上游原值，不自行加上自由空间项；旧云雨合并字段仍可读。 |
| 时延与路径参数 | 保存链路 `quality.delay`、路径 `path_params.delay/trans_freq/data_content`，按原值展示并标记单位待确认，不用于派生统计。 |
| 路径业务 | 从 `path_params.trans_type` 读取业务，兼容旧路径外层字段；初始路径和切换记录均展示。 |
| 旧路径 | 仅按同一运行、同一引擎轮次、方向、端点与 `old_path_id`，恢复最近收到的路径节点；最多缓存 1024 条。重启或换任务清空，未收到的历史不推断。 |
| 干扰设备 | 接入 `jammer_pos` 和 `rf_jammer.mode`，展示位置、模式、频率、范围和当前目标。 |
| 上游计时 | 保存 `wall_time_ms` 原值，显示毫秒及“起点待确认”，不用其计算通信延迟。 |
| 固定值与事件 | 固定值正常展示；`closed_loop.last_action` 保持为当前帧状态，不派生额外起扰事件或次数，不把空设备列表推断成停扰执行成功。 |
| 兼容性 | 新增归一化字段可选，旧归档仍可校验、读取，内部秒值不重复转换。现有规范 CSV 只检查自身必需字段，不因新增可选字段缺测而失效。 |

接入口统一采用新单位口径。仍发送旧秒值或探测 Hz 的上游需要同步调整；历史归一化归档无须重写。对接方原始文件及四份回归夹具保持原始字节。

## 单独保留的依赖与验收边界

当前目标为页面展示和功能流程测试；样例包含固定数据，本次通过不能替代真实引擎或现场实测。

| 对应项目 | 当前边界 / 后续需要 |
| --- | --- |
| GNZB-03/04：质量详情与报表 | 已有字段可展示、按秒筛选和归档；SNR、接收功率等缺测保持为空。时延、信息量及总损耗口径明确后，才能用于对应派生统计或物理正确性验收。 |
| GNZB-23：CSV | 新样例没有接收功率，也没有已约定的云雨合并值，规范状态/损耗 CSV 继续标记缺测；不放宽原有合同或补造数值。质量、切换、事件 CSV 的既有缺项继续保留。完整已接收内容可通过归档 JSONL 下载。 |
| GNZB-14～17：侦测、启停与闭环 | 固定 DETECTED/ON/JAM_ON 可验证展示。真实探测概率、指令执行/失败回执、目标消失后的停扰、参数版本与生效帧仍需引擎接口及联调。 |
| GNZB-18 等选路指标 | 当前热链与切换信息可展示，尚不能代替全部候选链路同帧数据、真实择优逻辑和稳定性验证。 |
| GNZB-25、XNZB-16/17 | 本机样例可验证接收、归一化、转发、去重与隔离边界。上游仍是单运行绑定；跨任务上游身份、引擎断线历史补发及真实 50 节点推送负载需另行对接/实测。 |
| 性能与现场 | 真实物理质量、时延、持续运行、国产部署环境和现场指标，均未以固定样例替代实测。 |

`frame_id`、毫秒仿真时间和 GHz 探测频率已确认，不再列为待确认项。先前仅凭帧号与时间数值关系提出的时间累计错误猜测，不作为本次缺陷结论。

补充：上游正常帧号步长为 5，与浏览器 WS 每主题消息序列号独立；原始四份样例是离散样例，不因这次口径确认而改写其帧号或时间。
