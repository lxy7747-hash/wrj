依据：V1.2 评审修改版测试大纲、`场景配置参数对接/websocketNew` 的四份帧样例及用户确认的单位口径。兼顾现有 `comm_PerDefinition` 模板，本次不修改模板，不纳入批量仿真。

## 本次已实现

| 内容 | 接入规则与结果 |
| --- | --- |
| 帧号与时间 | 2026-11-10 更新：取消 `sim_time_s`，缺失或遗留值均不参与校验。`frame_id` 正常按 5→10→15 递增，直接对应仿真秒数；例如 3770.0 对应 3770 秒。页面、筛选、WS 转发与新归档统一使用此秒值，已有归档保留已存时间。正常帧号差 5 不提示异常或打断曲线；非正常间隔记录诊断并保留曲线断点，不补造中间帧。 |
| 探测与干扰频率 | 探测器 `jammer_sensor.events[].freq_band_hz` 按 GHz × 10⁹ 转 Hz；干扰机 `rf_jammer.active_params.freq_band_hz` 保持 Hz。按字段位置转换，不按数值大小猜单位。 |
| 链路频率 | 优先读取 `quality.input_trace.frequency_ghz`，兼容旧字段名 `frequency`。页面显示 GHz。 |
| 损耗 | 雨衰、云衰分别接收、展示和归档。总复合损耗保留上游原值，不自行加上自由空间项；旧云雨合并字段仍可读。 |
| 时延与路径参数 | 保存链路 `quality.delay`、路径 `path_params.delay/trans_freq/data_content`，按原值展示并标记单位待确认，不用于派生统计。 |
| 路径业务 | 从 `path_params.trans_type` 读取业务，兼容旧路径外层字段；初始路径和切换记录均展示。 |
| 旧路径 | 仅按同一运行、同一引擎轮次、方向、端点与 `old_path_id`，恢复最近收到的路径节点；最多缓存 1024 条。重启或换任务清空，未收到的历史不推断。 |
| 干扰设备 | 接入 `jammer_pos` 和 `rf_jammer.mode`，展示位置、模式、频率、范围和当前目标。 |
| 上游计时 | 保存 `wall_time_ms` 原值，显示毫秒及“起点待确认”，不用其计算通信延迟。 |
| 固定值与事件 | 固定值正常展示；`closed_loop.last_action` 保持为当前帧状态，不派生额外起扰事件或次数，不把空设备列表推断成停扰执行成功。 |
| 兼容性 | 新增归一化字段可选，旧归档仍可校验、读取，内部秒值不重复转换。现有规范 CSV 只检查自身必需字段，不因新增可选字段缺测而失效。 |

接入口统一采用上述口径，旧 `sim_time_s` 不再影响时间轴。探测频率仍按 GHz 接入；历史归一化归档无须重写。对接方原始文件及四份回归夹具保持原始字节。

## 单独保留的依赖与验收边界

### 2026-11-10 最新连续帧复核

#### 两条实际报文的浏览器全流程联调

使用 `websocket-latest.json` 中的 3775/3780 两帧，临时本机 WebSocket 每 5 秒推送一帧，连接真实 4173 服务及 5173 页面。模拟端只响应约定的两字段 `pause/resume/stop` 命令，不发送虚构回执。未改写报文帧号或数值，未启动 mission.exe。

- 播放在首帧前即推进本地轨迹；收到帧后校准时间轴，帧间地图持续移动。
- 暂停冻结地图、时间轴和质量显示，停止周期 HTTP 状态轮询；暂停后刷新仍保持暂停。恢复后收到第二帧，质量值更新。
- 停止无确认弹窗，模拟端收到 stop 并关闭接收；文件时间归零，质量清空，按钮复位。再次播放创建新 runId、从零开始并重新连接，首帧前没有旧质量数据；旧归档不变。
- 修复文件与 WebSocket 并行模式停止后仅落盘、未发布运行结果的问题。结果发布与停止保存共用失败保护，发布失败保持锁定，重试不重复发送 stop。结果绑定播放时的文件指纹，拒绝混入已替换的文件，报表明确区分文件历史与本次接收的引擎帧。
- 修复 JSONL、规范 CSV 下载接口缺少跨域暴露 `Content-Disposition`，导致浏览器拒绝附件下载的问题。
- 修复报表来源和汇总较多时把明细页签压到零高度的问题，允许整体滚动并保留页签内容高度。
- 报表显示 2 帧、10 条链路段；筛选到 3780 秒后仅保留该帧 5 条段记录。实际点击下载 JSONL、HTML、PDF、报告 CSV 成功；JSONL SHA-256 与归档一致，全部归一化字段与输入报文一致。后端重启后结果仍可读取。重播检查另生成 2 帧和 1 帧两份独立结果，未混入前次数据。
- 本轮相关回归按每个测试文件最后一次结果汇总：360 项通过、0 失败、1 项已有真实引擎测试跳过；类型检查通过。证据见 `output/latest-flow-20261110/validation-summary.json`，实际导出文件位于同目录。完整流程结果编号 `RESULT-17998638-e921-45c8-8abc-54371dd4d50a`。

本次验证范围是当前“文件与 WebSocket 并行”操作。规范五类 CSV 因原报文缺字段继续标记缺源，完整内容保存在 JSONL 与报告导出中。测试完成后恢复 `ws://192.168.1.48:8080/ws/v1` 并关闭临时模拟服务；模拟端执行成功不代表真实引擎执行成功。真实控制效果、控制回执、未确认单位与损耗口径、现场性能继续待验证。
