# 文件与 WebSocket 并行播放整改与验收

日期：2026-11-09。按 V1.2 大纲、新模板及 websocketNew 口径整改；批量仿真不纳入。

## 当前操作

- 进入态势页先读取文件和当前运行状态，不自动新建上游连接。点击“播放”，同时播放本地轨迹/事件文件并建立 WebSocket 接收会话，不启动 mission.exe，也不发送未定义的 start 报文。
- 页面只保留“播放／暂停／停止”。暂停立即冻结文件游标、地图和已呈现的实时质量/事件；连接允许控制时发送 `{"msg_type":"sim_control","action":"pause"}`。
- 暂停后再次点“播放”，在可发送时发送 resume，并同步到最新已接收帧。断线或 UNKNOWN 时仍可暂停/恢复本地画面，页面明确保留远端未连接或执行待确认提示，不自动补发控制命令。
- 点击停止直接执行，不弹出确认框：可发送时发送 stop，断开接收和重连计时器；等待归档完成后解锁，本地游标归零并清除实时展示。归档失败保留锁，停止可重试保存，不重复发送 stop。

## 统一时间和来源

收到第一条有效实时帧前，文件按本地计时播放；收到后用帧内仿真时间驱动同一个文件游标并停止本地计时器。暂停时即使远端继续发帧，页面也冻结，服务端仍留存；页面只暂存最近 200 帧用于恢复展示，完整数据在服务端归档。

`sim_time_s` 按毫秒除以 1000 转内部秒；`frame_id` 是帧号，正常间隔 5 对应 5 秒；探测频率按 GHz 转换。同步期间禁用拖动时间轴和倍速，因为后台尚无对应控制协议。文件到末尾保留最后位置，实时接收继续，页面提示轨迹已到末尾；断线后不另起时钟冒充实时推进。

文件会话校验事件文件和位置文件的完整 SHA-256。运行使用 `fileSource` 和独立的 `SCN-FILE-…` 来源编号，**不新增或修改已保存场景**；实时链路按文件原始平台名和端口绑定到稳定的 `FILE-LINK-N`。不将当前 9 节点文件套用到另一份 50 节点场景。文件更换时拒绝串用旧接收任务；需先停止旧任务再重新播放。无文件时仍兼容原有场景接收路径，未配置远端地址时保留原文件播放/本机执行路径。
