# 1112 固定模板脚本生成说明

日期：2026-11-13。适用代码：`server/scripts/mission-generator.ts`、`server/scripts/afsim-template-1112.ts`、`server/scripts/afsim-template-patch.ts`。

## 1. 模板来源与稳定资源

- 唯一基准：`H:/Project/newWrj/场景配置参数对接/afsim_script_lcm_1112/afsim_script_lcm`（只读，不修改）。
- 仓库逐字节副本：`tests/fixtures/afsim-template-1112/`，清单与 SHA-256 见 `tests/fixtures/afsim-template-1112.source.json`。
- 运行时资源：`server/scripts/afsim-template-1112.ts`，由 `npx tsx scripts/generate-afsim-template.ts` 从仓库副本生成；十六进制编码只为避开服务端源码边界检查，解码后与模板逐字节一致。
- 生成器以 1112 模板为基准做受控替换：`comm_platform_INS.txt` 的 mission_uav 实例段按场景配置生成（数量、阵营、初始位置、航点、盘旋、返航、角色），其余平台实例（后方车、指挥车、卫星、干扰站）、通信平台、天线、网络、观察者和固定执行逻辑保持模板原文。

## 2. 允许变化的精确边界

| 文件 | 区域 | 定位标记 | 变化内容 |
|---|---|---|---|
| `comm_platform_INS.txt` | mission_uav 实例段 | `// 无人机编队` 注释块起，至 `platform jammer_station_01` 前最后一个 `end_platform` | 替换为按场景生成的 mission_uav 实例块（数量/阵营/初始位置/航点/盘旋/返航/角色）；中继与作业无人机按 `mission_uav_01…` 连续编号 |
| `comm_platform_REAR.txt` | `fw_sit_dst` 数组 | 唯一 `Array<string> fw_sit_dst =` 行 | 只替换 `{ ... }` 元素，保留行尾 `;\\` |
| `comm_platform_REAR.txt` | `fw_tgt_dst` 数组 | 唯一 `Array<string> fw_tgt_dst =` 行 | 只替换 `{ ... }` 元素，保留行尾 `;\\` |
| `comm_platform_REAR.txt` | `link_calc` 参数块 | 唯一 `add processor link_calc WSF_LINK_CALC_PROCESSOR` 到其后首个 `end_processor` | 参数名称/顺序不变；不输出 `jamming_range` |
| `comm_platform_MISSION_UAV.txt` | `relayNames` 数组 | 唯一 `Array<string> relayNames =` 行 | 只替换元素 |
| `comm_platform_MISSION_UAV.txt` | `rt_video_dsts` 数组 | 唯一 `Array<string> rt_video_dsts =` 行 | 只替换元素 |
| `comm_platform_MISSION_UAV.txt` | `rt_status_dsts` 数组 | 唯一 `Array<string> rt_status_dsts =` 行 | 只替换元素 |
| `comm_platform_MISSION_UAV.txt` | `sat_link` 接收频率 | 模板中的唯一 `frequency 11.8 MHz` 行 | 生成时将单位修正为 `GHz`，与卫星下行一致 |
| `comm_SimSetup.txt` | `realtime` 指令 | 唯一 `realtime` / `//realtime` 行 | 启用写 `realtime`，全速写 `//realtime` |
| `comm_SimSetup.txt` | `clock_rate` 指令 | 唯一 `clock_rate <数值>` 行 | 写所选倍速 |

区域定位失败或匹配多处时抛 `TemplateRegionError`，由生成器转成 `MissionGenerationError`，不静默使用第一个匹配。

交付与预览的执行 TXT 会去除注释：整行 `//`、整行 `#` 以及字符串外的行尾 `//` 注释均不输出；全速档不输出 `realtime` 行（等价于模板中的 `//realtime`）。模板基线比较按去注释后的语义内容进行，`mapping.json`、`input.json`、`README.txt` 等资料文件不受影响。交付 TXT 的 `port_params.eirp_dBW` / `G_T_dBK` 采用端口配置值（缺省为模板值，2026-11-19 用户确认可配置后调整）；`jammer_param.weapon_eirp_dBW` / `weapon_antenna_gain_dbi` 采用干扰设备配置值（缺省为模板值），配置快照保留原值。

激光端口统一为 `lazer_link`：只替换 `comm laser_link`、`"comm_name":"laser_link"`、`Comm("laser_link")` 三类明确指向同一端口的声明/引用，不做全局替换。1112 源模板已使用 `lazer_link`，当前命中 0 处；项目内旧副本的 `laser_link` 已按源模板更正。

## 3. 倍速字段与输出

字段仍为既有可选字段：`scenario.realtime`（缺省=实时）与 `scenario.environment.simClockSpeed`。

| 下拉值 | realtime | clock_rate |
|---|---|---|
| 全速 | 不启用（`//realtime`） | 32 |
| x1 | 启用（`realtime`） | 1 |
| x2 | 启用 | 2 |
| x4 | 启用 | 4 |
| x8 | 启用 | 8 |
| x16 | 启用 | 16 |
| x32 | 启用 | 32 |

- 全速与 x32 的 `clock_rate` 都是 32，但 realtime 状态不同，不能合并。
- 旧场景缺少 `simClockSpeed` 时沿用既有生成器约定 `clock_rate 2`；缺少 `realtime` 时按实时处理，即 x2。
- 非实时但倍速非 32 的旧组合按原值保留，界面显示为不可选择的“当前：非实时 / N×（旧场景）”，不静默改写。
- 非法（≤0、非有限数）在生成前报错。

## 4. 场景配置到 link_calc 的映射

- `update_interval` ← `linkSettings.linkCalc.updateIntervalS`（缺省 5）。
- `emergency_threshold` / `warning_threshold` / `value_threshold_ber` / `channel_encoding_scheme` ← `linkSettings.linkCalc`。
- `traffic_type` ← 启用业务的方向、信息类型、数据量、频次及源/目标平台；按目标平台分组。
- `traffic_distance` 取场景的链路最大传输距离，未配置时使用模板默认值。所有 `distance` 值的单位均为千米（km）。交付 TXT 和本机 Mission 运行包均保留该指令，本机运行需要支持该指令的 LinkCalc DLL。
- `relay_uav_names` ← `FORWARD_RELAY_NODE` 的模板实例名。
- `hot_link_fw` / `hot_link_ret` ← `linkSettings.hotLinks`；显式热链引用不存在/停用链路、方向不一致或跳点不相接时生成前报错。
- `port_params` ← 1112 `port_params` 基准 + `deviceParameters.ports` + 绑定链路显式字段；单位按模板键换算。模板 comm 段固定，不随设备参数改写。
- `natural_environment` ← `scenario.environment` 的降雨、云雾、大气、极化失配、海况。
- `jammer_param` ← 干扰设备的雷达/武器参数、探测/触发/释放半径、模式；未配置字段取模板基准（地面 G_T -12 / eirp 50 / 增益 30，机载 G_T -10 / eirp 40 / 增益 25）。

## 5. 固定实例与失败路径

`comm_platform_INS.txt` 的固定实例为 6 个非无人机平台：`rear_comm_vehicle`、`command_vehicle`、`tiantong_sat`、`shentong_sat`、`jammer_station_01`、`jammer_airborne_01`；mission_uav 实例段按场景配置动态生成，中继与作业无人机按 `mission_uav_01…` 连续编号，容量遵循场景规则（中继 ≤2、作业无人机 ≤61、四类信息节点合计 ≤64）。

- 非无人机平台必须映射到固定实例；重复占用、名称无法映射时生成前报错并指出 `platforms[i].id`。
- mission_uav 的阵营、初始位置、航点、盘旋和返航写入 INS；航点的航向/加速度/到达时间不写入。
- 模板 JAMMER 脚本固定引用 `mission_uav_02` / `mission_uav_03`；无人机数量不足或编号被中继占用时，生成器在 `mapping.warnings` 中提示，不修改模板脚本。
- 旧 54 平台包（`output/scripts/script-20261113095332/metadata/input.json`）现在可生成 mission_uav_01…48；仍需真实引擎验证 60/64 节点的性能与输出规模。

## 6. 本地运行包

交付 TXT 不含本地适配。`buildMissionPackage(..., runtime)` 仅对运行副本：

- 将模板固定 `start_date` / `start_time` / `end_time`、事件 CSV/AER 路径和 `observers` 输出路径适配为本次运行目录；
- 每个射频端口派生独立介质（`UAV_MESH_MEDIUM__<平台类型>__<端口>`）；
- 引擎缺少 `WSF_LINK_CALC_PROCESSOR` 时以 `local_link_stub` 原位替换 `link_calc` 块。

## 7. 模板已知差异

1. 原模板的 `sat_link` 接收频率写作 `11.8 MHz`，生成的交付及本地运行包使用 `11.8 GHz`。
2. `comm_platform_REAR.txt` 两个数组行尾带反斜杠；生成时去除行尾反斜杠，避免 AFSIM 语法错误。
3. 地面站 `prophet_jammer` 武器块在模板中被注释，交付包不补造定义。
4. 模板 `jammer_param` 的机载项写 `prophet_jammer`，生成器按实际机载武器写 `alq99_jammer`，待对接方确认。
5. 模板固定 `SetSizeInBits(8)` 与 `link_calc traffic_type.data_volume_bits` 的语义不一致；未修改固定执行逻辑，也未重新引入 `size` 变量。不同无人机的数据量差异只进入 link_calc，并在 mapping 中给出限制说明。
6. `MISSION_UAV` 的 `rt_video_dsts` / `rt_status_dsts` 是平台类型级共享数组；若不同无人机返向目的地不同，模板无法按无人机分别表达，生成器合并数组并在 mapping.warnings 中明确报告。
7. `comm_SimSetup.txt` 保留模板绝对输出路径；本地运行包另行适配。
