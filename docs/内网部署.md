# Windows 内网单机部署

麒麟 Linux x86_64 的仅网页验证见[麒麟网页验证](./麒麟网页验证.md)。

本说明对应本次新增的内网发布入口。一个 Express 服务提供前端静态页面、API、WebSocket 和地图转发；VersaTiles 独立运行并只监听本机。无需额外安装反向代理即可用 HTTP 验收。

## 1. 地址与服务

以 `http://192.168.1.10:8080` 为例，实际替换为服务器地址：

| 浏览器访问 | 服务 |
| --- | --- |
| `/`、`/login`、`/situation` 等 | 内网构建的前端页面，支持直接刷新业务路由 |
| `/api/v1/...` | 同一个 Node.js 进程中的真实账号库及业务 API |
| `/ws/v1` | 同一个 Node.js 进程中的 WebSocket，必须通过会话和 Origin 校验 |
| `/tiles/...` | 固定转发到 `127.0.0.1:4174`，不转发浏览器 Cookie |

客户端只需浏览器。只向需要访问的内网网段开放 Web 入口端口；地图端口无需对客户端开放。当前部署仍是单实例、一次执行一个仿真。

## 2. 在开发机生成发布文件

在 `frontend` 目录使用项目锁文件安装依赖并构建：

```powershell
npm ci
npm run typecheck
npm run validate:contracts
npm run build:lan
```

`build:lan` 生成 `dist/` 和 `server-dist/`。必须使用这个命令：普通 `npm run build` 继续用于原有本机开发/预览流程。内网服务会检查发布标记，拒绝加载普通开发构建。

后端构建已包含它引用的业务源码和 JSON 数据，整个 `server-dist/` 都需要复制，不能只复制 `server.mjs`。不需要部署 TypeScript 源文件、测试或设计文档。

本机验证使用 Node.js v22.14.0（包含 `node:sqlite`）；构建和运行机器使用团队验证过的兼容 Node.js 版本。当前 SQLite 运行时会打印实验性功能提示。

## 3. 服务器目录

建议按以下目录复制，应用与私有数据分开：

```text
C:\wrj\
  app\
    dist\                        前端发布文件
    server-dist\                 全部后端构建文件
    scripts\start-lan.mjs         聚合启动器
    scripts\start-tiles.mjs       地图启动器
    package.json
    package-lock.json
    .env.server.example
    .env.server                  按模板创建；不提交版本库
  data\                          SQLite 数据库与备份
  output\                        运行包、脚本、报告
  maps\
    china-taiwan-260823.pmtiles
    taiwan-strait-satellite.pmtiles
  tools\versatiles.exe
  engine\                        配套引擎目录的完整内容，包括 mission.exe、DLL、插件和资源
```

地图文件被 Git 忽略，必须单独复制并保留上述文件名。引擎不能只复制一个 EXE。数据库、引擎及输出目录不得位于 `dist/` 中。

迁移已有业务数据时，先正常停止原服务，再完整备份和复制 `data/`，包括其业务数据库及 `backups/`。不要对正在写入的数据库做零散文件复制。全新安装先创建空的 `data/` 目录，由程序初始化。

在服务器 `C:\wrj\app` 中安装运行依赖：

```powershell
npm ci --omit=dev
Copy-Item -LiteralPath .env.server.example -Destination .env.server
```

只在首次配置时复制模板，不要覆盖已有 `.env.server`。隔离网络应提前准备匹配平台的 npm 依赖缓存或安装产物。

## 4. 配置与启动

修改 `.env.server`：

```dotenv
WRJ_DEPLOYMENT=lan
WRJ_PUBLIC_ORIGIN=http://192.168.1.10:8080
WRJ_HOST=0.0.0.0
WRJ_PORT=8080
WRJ_WEB_ROOT=C:/wrj/app/dist
WRJ_OUTPUT_ROOT=C:/wrj/output
SCENARIO_DB_PATH=C:/wrj/data/scenarios.db
MISSION_EXECUTABLE_PATH=C:/wrj/engine/mission.exe
WRJ_MAP_PORT=4174
WRJ_MAP_EXECUTABLE_PATH=C:/wrj/tools/versatiles.exe
WRJ_MAP_VECTOR_PATH=C:/wrj/maps/china-taiwan-260823.pmtiles
WRJ_MAP_SATELLITE_PATH=C:/wrj/maps/taiwan-strait-satellite.pmtiles
# 非 Windows 部署真实 PDF 报告必须配置可嵌入的中文 TTF 或 OTF；生成文件会嵌入字体，接收端无需安装。
WRJ_PDF_FONT_PATH=C:/wrj/fonts/NotoSansSC-Regular.ttf
```

`WRJ_PUBLIC_ORIGIN` 必须与浏览器访问地址完全一致，包括协议和非默认端口。配置为 IP 后，使用其他主机名访问会被拒绝；修改服务配置后重启即可，不必重新构建前端。应用直接提供 HTTP，使用 HTTPS 地址还需要另行配置 TLS 入口，不能只把此变量改成 https。

全新账号库需要在首次启动环境配置 `AUTH_BOOTSTRAP_PASSWORD`（12–128 位，不能全为空白），用于初始化 `admin`。初始化后从配置文件删除这一项；已有账号库继续使用原账号密码。程序不会退回演示登录。

```powershell
npm run start:lan
```

启动器先检查 Web/地图端口空闲，再启动地图并验证两份 TileJSON，最后启动 Web 服务。端口被占用或子进程退出会明确失败，停止本次启动的关联子进程，不接管或终止未知服务。

Ctrl+C 正常停止本次启动的服务。Windows 下启动器通过 IPC 请求后端关闭存储和正在执行的 mission，再退出；异常超时会报告兜底终止。

也可由已有的服务托管工具分别运行以下命令，工作目录都设为 `C:\wrj\app`：

```powershell
npm run start:tiles
npm run start:server
```

不要同时运行聚合启动器和独立启动命令。当前提交提供启动/停止脚本，不自动安装 Windows 服务、不修改防火墙、不添加开机任务。日志写到进程标准输出/错误，由服务器的托管工具收集。

内网入口不会加载开发机 `.env.local`。若需要读取已有的事件/位置文件，设置模板中的 `AFSIM_EVENT_LOG_PATH` 和 `AFSIM_POSITION_LOG_PATH`；留空时相应功能明确返回未配置。

真实 PDF 报告不使用浏览器打印或 HTML 伪装文件。Windows 优先使用已安装的等线或黑体 TTF；其他系统应通过 `WRJ_PDF_FONT_PATH` 配置一个允许嵌入的中文 TTF 或 OTF。PDFKit 不能直接注册 TTC 字体集合，路径不可读、使用 TTC 或字体无法嵌入时，导出明确失败，不会返回错误格式的“PDF”。

网页启动的真实仿真会自动绑定本次 `WRJ_OUTPUT_ROOT/mission-runs` 下独占生成包的 `position.csv`，运行中更新态势地图，无需把新 CSV 复制到上述配置路径或 `input`。本次输出与既有文件播放相互独立，见[运行中的态势位置](./仿真结果闭环.md#运行中的态势位置)。

### Mission 异常退出后的人工核实

真实 Mission 启动前会在 `WRJ_OUTPUT_ROOT/mission-runs/.mission-active/record.json` 留下未结清记录（本机开发模式位于 `frontend/output/mission-runs`）。记录含运行、场景及修订号；进程启动后补记 PID、启动时间和独占运行目录。Node 异常退出后，记录存在或损坏都会阻止新的真实运行；能识别场景时也阻止该场景写入。服务不会自动接管、续跑或仅凭 PID 消失就解除拦截。

管理员须先停止 Web 服务，核对记录、运行目录和操作系统中的 `mission.exe` 进程；PID 可能复用，不能仅凭 PID 数字判断。确认旧进程及其后代均已终止、不会再写本次输出后，保留记录副本，将整个 `.mission-active` 目录移出 `mission-runs` 并归档，再启动服务。记录损坏或进程归属无法确认时保持拦截，不移动记录；必要时由管理员线下排查。正常收到进程关闭信号时程序自行清除记录，无需人工处理。

## 5. 验收

1. 另一台内网电脑访问配置地址，登录后直接刷新 `/situation`，页面正常。
2. 浏览器网络面板中的 API、WebSocket、矢量和卫星瓦片全部使用统一入口；不能请求客户端自己的 4173/4174。
3. 退出后受保护 API/WS 拒绝访问；错误 Host、外站 Origin 和缺少来源的写请求被拒绝。
4. 停止地图服务，地图请求返回明确失败；使用聚合启动器时相关服务一并退出。
5. 正常停止后端再重启，已有账号和场景保留，用户重新登录。
6. 原有 `npm run dev` 仍可用于本机开发。

单次仿真结果自动关联、回放、HTML/CSV 浏览器下载和已完成结果重载已接通，见[仿真结果闭环](./仿真结果闭环.md)。运行中的任务恢复、独立脚本包下载、Windows 服务托管和异机备份仍待后续改造。

## Windows 部署包的后台启动与停止

将代码更新包完整解压到包含 `start.cmd` 的 Windows 部署根目录。后台入口位于根目录的 `scripts` 下，不是 `app/scripts`：

- 双击 `scripts/dev-start-hidden.vbs`：使用 `runtime/node.exe` 和原有 `app/.env.server` 启动发布服务，服务就绪后打开配置的访问地址。重复点击复用已启动的后台实例。
- 双击 `scripts/dev-stop.cmd`：通知该部署实例正常关闭网页、地图及它启动的仿真，并等待关闭完成。只控制上述后台入口启动的实例，不按进程名称或端口查杀其他服务。
- 日志位于 `logs/background.log`；后台控制状态位于 `logs/deploy-background.state.json`。服务运行时保留状态文件，不要手工修改或删除。

两个文件保留历史名称，现为部署版脚本，使用发布产物而非 `npm run dev`。源码开发仍使用 `npm run dev`。原 `start.cmd` 的前台启动方式继续可用；由它启动的服务仍在原窗口按 Ctrl+C 停止，不与后台入口同时运行。后台入口不设置开机自启，也不替代 Windows 服务托管。若系统禁用 VBS，可在部署根目录执行：

```cmd
runtime\node.exe --env-file=app\.env.server scripts\deploy-background.mjs start --open-browser
runtime\node.exe --env-file=app\.env.server scripts\deploy-background.mjs stop
```

更新文件前先正常停止服务。地图、数据库、CSV、已有结果及服务器配置沿用原部署；`.env.server` 已配置的绝对路径优先，未配置时按部署根目录定位。首次安装所需的 VC++ 运行库仍由完整包的 `deploy.cmd` 处理。

### 桌面快捷方式图标

为上述启动、停止脚本创建桌面快捷方式，在快捷方式“属性 → 快捷方式 → 更改图标”中分别选择部署根目录下的 `scripts/icons/wrj-start.ico`、`scripts/icons/wrj-stop.ico`。图标沿用项目通联标志，启动用青绿色播放标记，停止用红色方块；设置后保留图标原位置。具体步骤见[图标说明](../scripts/icons/README.md)。

## 干扰延迟与持续时长（本地运行包）

这两个可选字段留空时，前端省略相应键。这两个字段已接入本地 link_calc 缺失时的 mission stub，对接方 TXT 不变。延迟从进入触发半径开始，离开触发半径取消等待；持续时长到期后须离开释放半径才重新就绪。检查周期 3 秒，存在约 ±3 秒误差。配置保存成功不能作为引擎时序执行证据。

最后一项干扰延迟／持续时长 stub 实测放在具有 `Release/Release/mission.exe` 的机器上，用 `npm run dev` 启动本机模式，再通过实际 mission 日志核对延迟和启停时刻。不得以投影层或测试替身通过替代真实引擎结论。

## 外部引擎链路帧（2026-11-07）

可选配置 `LINK_ENGINE_WS_URL=ws://192.168.1.48:8080/ws/v1`：本机开发填入 `.env.local`（参考 `.env.example`），内网部署填入 `.env.server`。设置后采用独立远端接收，不再要求配置或安装 mission.exe；未配置时保持原有本机执行行为。配置生效需要重启本项目后端；浏览器仍连接本项目 `/ws/v1`，不直连外部服务，也不改变 REST、地图或登录入口。

选择已保存场景后点击“播放”，直接建立上游连接及独立归档，不启动本机进程，也不发送上游 START、登录或订阅消息。暂停后再点“播放”发送 resume。点击“停止”经二次确认后，可发送时发送 `sim_control/stop`，随后断开本地连接并保存数据，归档成功才解锁。断线时仍可停止本地接收，保存失败可再次点停止重试；发送方执行结果持续标记待确认，不增加额外结束按钮。服务关闭也会收尾归档。断线按 1、2、5、10 秒退避重连，不补发控制命令。一次仅绑定一个接收会话；上游没有运行编号，仍需部署方确认数据与所选场景及命令目标相符。

从已保存场景独立生成与新模板一致的实例名和通信端口映射，还原平台编号并绑定链路段；不要求先生成或执行 mission 包。中继拆成两段，共用段可对应多个场景链路。未匹配的段保留发送方名称。严格 JSON 解析失败或帧头无效时记录丢弃计数与最后错误，连接继续工作。坏帧和过期帧按原因限流记录日志，同一原因每 10 秒最多一条，并包含累计丢弃次数。

每次新运行的 `engineEpoch` 从 0 开始；收到帧号 0 且上一帧大于 0，或重连后的首个有效帧号小于上一帧时，视为引擎重启：递增 `engineEpoch`、清空初始热链缓存并接受新帧。前端收到更大轮次后清空引擎帧、事件、切换和告警历史；更小轮次拒绝，同一轮次只接受递增帧。普通重连且帧号递增时保留缓存，其余重复／倒序帧丢弃。中途订阅与断线重放沿用现有每主题 128 条热缓存及部署日志机制，不另写引擎帧文件到运行包。

整帧以 `link.metric` 的 `ENGINE_FRAME` 载荷转发，WebSocket 信封帧号为 `F-ENGINE-<frame_id>`，载荷保留数值帧号。态势页显示引擎状态、链路质量、初始热链、切换、告警、探测和干扰证据，事件／切换／告警各保留最近 200 条。引擎状态直接展示，不再次进入本机连续帧判定，也不将设备段状态自动当作整条多跳场景链路的状态。缺测值显示“暂无数据”；单段 error_msg 不影响其他段。

2026-11-09 按 `websocketNew` 更新：`frame_id` 是帧号；`sim_time_s` 实际为毫秒，接收入口除以 1000，内部展示、筛选及归档使用秒；探测器 `jammer_sensor.events[].freq_band_hz` 实际为 GHz，乘以 10⁹ 转 Hz，干扰机 `rf_jammer.active_params.freq_band_hz` 保持 Hz。链路频率优先读取 `input_trace.frequency_ghz`，兼容旧字段名 `frequency`；不按数值大小猜测单位。已归档的归一化数据保持秒值，不重复换算。当前接入口统一遵守新单位口径，发送旧秒值/探测 Hz 的上游需同步调整。

新增雨衰、云衰、原始时延、路径业务及参数、干扰站位置/模式和上游计时已接入。总损耗保留原值；未确认单位的参数不参与派生统计。引擎帧可归档、回读和下载，缺少字段的规范 CSV 继续标记缺测，不补造数据。当前数据含固定值，仅用于展示和流程测试；真实物理计算、启停闭环、推送性能及上游补发仍需联调。详见 [websocketNew 适配与待验证清单](websocketNew适配与待验证清单_20261109.md)。对接方 TXT 不变；本地 WebSocket 样例测试不替代实机联调。

帧间隔补充确认：`frame_id` 正常按 `5 → 10 → 15` 递增，每次仿真推进 5 秒，`sim_time_s` 相应增加 5000 毫秒。正常帧号差 5 不触发间隔异常，页面与 HTML/PDF 引擎曲线按此保持连续；差值异常仍记录并保留曲线断点，不补造中间帧。WS 信封的每主题 `sequence` 仍逐消息递增，不改成加 5；文件质量采样序号的既有约定也不受影响。

WebSocket 控制补充（2026-11-09）：运行绑定且连接建立后开放暂停，发送 `{ "msg_type": "sim_control", "action": "pause" }`；发送完成后可再次点击“播放”发送 `resume`，停止沿用二次确认发送 `stop`。报文不附加其他字段。界面持续显示“执行结果待确认”，不会将发送状态改为引擎已暂停。发送中禁止并发；发送结果不确定时限制恢复和暂停，但仍可停止本地播放；断线后不会自动重发。未配置 `LINK_ENGINE_WS_URL` 时保留原本机开始/停止行为，单步与倍速仍未接入。详见 [WebSocket 控制接入与待验证清单](WebSocket控制接入与待验证清单_20261109.md)。更新部署需重新构建、替换应用并重启服务；本次代码和测试未自动部署到其他机器。
