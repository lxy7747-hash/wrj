# WebSocket 写盘积压与停止保存重试

2026-11-10。保留浏览器 → 4173 → `ws://192.168.1.48:8080/ws/v1`，不改变播放、暂停、恢复、停止按钮或后台两字段控制协议。

## 原因与修复

原来 WebSocket 接收回调不等待归档写入。突发帧会积压超过 512 帧，且未入队的帧已计入摘要和帧数；首次关闭失败后缓存了失败 Promise，并删除临时文件，后续停止无法真正重试。

- `server/local/engine-snapshot-client.ts`：使用现有 ws 库的消息流逐帧等待处理，慢盘时向网络读取施加背压。保持文本帧校验、运行隔离、控制发送与断线重连；旧连接异步收尾不会修改新运行。
- `server/app.ts`：等待归档追加后才转发页面数据，立即发现写盘失败并停止接收、保留运行锁。停止继续等待已进入归档的帧，归档和报表都成功后才完成收尾；重试不重复发送 stop。
- `server/local/engine-frame-archive.ts`：保留失败帧及临时文件，写入成功才更新摘要和帧数。半行写入重试使用原偏移覆盖，避免重复或损坏 JSONL。保存按已完成步骤继续，失败不会永久缓存第一次错误。
- `server/local/engine-frame-csv.ts`：CSV 失败可从完整 JSONL 重新生成，包含明确零帧的空运行；保留来源摘要、帧数、作用域和缺测字段校验。

保存失败时页面保持冻结、运行保持锁定，已展示数据保留。磁盘空间、权限或占用问题排除后再次点击“停止”；保存成功后页面归零，旧结果仍可回读和导出。
